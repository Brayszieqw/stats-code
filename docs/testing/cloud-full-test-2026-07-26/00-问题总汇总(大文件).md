## 一、确认缺陷（可复现、属产品问题）

### 🔴 高优先级（3 项 + 1 能力缺口）

#### D11 · 审计主键白名单导致 UI 内死锁
- **现象**：数据集审计只认 7 种主键列名（`participant_id / subject_id / patient_id / person_id / record_id / study_id / case_id`）。列名叫 `id`、`rownames` 或任何其它命名 → 报 `PRIMARY_KEY_UNBOUND`（blocker）；而用户通过 roles 显式指定主键，又被 `AUDIT_ROLE_OVERRIDE_REJECTED` 拒绝。结果：**没有白名单列名的数据集在界面里彻底走不下去，只能改列名重新上传，且 UI 无任何引导**。
- **位置**：`ts-backend/packages/server/src/conversation/dataset-audit.ts`（PK 启发式 + AUDIT_ROLE_OVERRIDE_REJECTED）
- **复现**：上传 R 原生 mtcars（列名含 `rownames`）→ 任意分析审计 → `blocked: PRIMARY_KEY_UNBOUND`；尝试 roles.primary_key=['rownames'] → 追加 `AUDIT_ROLE_OVERRIDE_REJECTED`
- **证据**：记录04 §5、`证据/stats-public.jsonl`（改名 mtcars_api 后才通过）
- **建议**：允许"经用户确认并记入审计"的主键绑定；或上传时引导用户指定主键；至少放宽到 `id`/`rownames` 等通用命名

#### D12 · 列名含 weight/wt 被误判抽样权重，整库阻断且不可覆盖
- **现象**：权重启发式把列名 `weight`、`weights`、`wt` 一律当成抽样权重 → `SURVEY_DESIGN_UNSUPPORTED`（blocker）阻断整个数据集分析，且无法覆盖。生物统计里 `weight` 极常见作为**结局或协变量**（出生体重、植物重量、体重…）。R 内置 PlantGrowth（结局列就叫 `weight`）原样上传后**永远无法分析**。
- **位置**：`dataset-audit.ts` 第 100-103 行权重启发式（正则 `/^...?(weight|weights|wt)$/`）
- **复现**：上传含 `weight` 列的任意 CSV → 审计 → `blocked: SURVEY_DESIGN_UNSUPPORTED`
- **证据**：记录04 §5、`证据/stats-public.jsonl`（plantgrowth 改名 plant_weight 后才通过）
- **建议**：权重判定应结合角色声明/数据特征而非纯列名匹配；或提供"这不是抽样权重"的显式否认入口

#### D17 · 用户数据条件被引擎抛错 → 返回 HTTP 500 而非 422（新发现，扫尾第2轮）
- **现象**：一类"合法通过审计但数学上退化"的用户数据，引擎抛出带清晰消息的异常，但**HTTP 状态是 500 `SkillExecutionFailed`（服务器故障语义），应为 422（用户输入问题）**。已确认 4 个子例：
  - 相关分析的 y 为常量列（零方差）→ 500 "requires y to have non-zero variance"
  - t 检验/ANOVA 分组只有 1 个水平 → 500
  - t 检验某组只有 1 个观测（无法算方差）→ 500
  - 线性回归自变量完全共线（x2=2·x1）→ 500
- **位置**：`skill-runner.ts` 异常→HTTP 映射；引擎各算法的 throw 本身是对的（防护正确），错在状态码分类
- **复现**：见 `证据/final-sweep.jsonl` 的 corr-constant-col / ttest-single-group / ttest-singleton-group / linear-collinear
- **影响**：前端把 500 当"系统崩了"提示，用户以为是 bug 而非自己数据的问题；也污染错误监控
- **建议**：这类"数据不满足方法前提"的引擎异常统一映射为 422，并把引擎的清晰消息透传给用户

#### G2 · 引擎 17 算法，只有 8 个能从 API/UI 实际运行（能力缺口）
- **现象**：`/api/.../run` 的分发 switch 只实现 8 个算法（tableone/ttest/anova/correlation/linear/logistic/cox/kaplan_meier）+ power/inspect（native）。以下 6 个引擎有完整实现、有等价代码模板、覆盖矩阵也宣示，但**没有任何 HTTP/UI 运行通路**，调用 `/run` 返回 422"未知统计方法"：`nonparametric（Mann-Whitney）、or_rr、attributable_risk、standardization、life_table、diagnostic_roc`。power 家族 3 个（single_arm/phase2/phase3）也只合并成一个 `power` skill 暴露。
- **位置**：`skill-runner.ts` switch（1139 行起）vs 配置器只有 7 个模块按钮
- **复现**：`POST /api/sessions/{id}/run` skill_id=`or_rr` → 422；配置器界面无这些方法入口
- **证据**：记录04 §5、记录06 §1.2
- **说明**：覆盖矩阵 21 条断言这些算法"live/recorded"，但界面能力≠引擎能力，宣示与可用面不一致
- **建议**：补齐分发与配置器模块；或在矩阵/文档中明示"引擎级能力"vs"界面可运行"分层

### 🟡 中优先级（8 项）

#### D1 · 非法 base64 被宽松解码为乱码数据集
- **现象**：上传 `data: "!!!not-base64!!!"` → 返回 201，生成 0 行、列名为乱码 `��~m�` 的数据集，未报错
- **位置**：dataset 上传 base64 解码（Node `Buffer.from(s,'base64')` 静默忽略非法字符）
- **复现**：记录03 dataset-bad-base64 · **建议**：严格校验 base64，非法→422

#### D2 · 编码检测缺陷：GBK 与 UTF-16 都被误判 Utf8 → 中文列名乱码（扫尾扩大）
- **现象**：契约 `Encoding` 枚举含 `Gbk / Utf16`，但实测：GBK CSV（"组别/数值"）→ 判 Utf8，列名变 `���/��ֵ`；UTF-16 CSV → 同样判 Utf8，列名变 `���~+R / \x00pe<P`。**Utf16/Gbk 枚举从未真正产出**。
- **位置**：dataset-store 编码探测
- **复现**：记录03 dataset-gbk + `证据/final-sweep.jsonl` utf16-upload
- **影响**：中文用户 Excel 另存 CSV 常为 GBK/ANSI 或 UTF-16，会直接得到乱码列名
- **建议**：按 BOM 检测 UTF-16；对无效 UTF-8 序列回退 GBK 探测

#### D3 · sidecar 传空 columns（schema 默认值）→ 500
- **现象**：`POST /api/sidecar/{alg}` 不带 columns（schema 默认 `[]`）→ 500 "column index 0 is out of range (have 0 columns)"。契约允许的最小合法输入把服务器打崩。
- **位置**：sidecar 渲染 · **复现**：记录03 sidecar-ttest-4langs（带 columns 则正常）· **建议**：空列占位渲染或 schema 要求非空

#### D10 · 教科书基线数据损坏（Kleinbaum linear）
- **现象**：`tests/parity/known_values/linear_textbook_kleinbaum.json` 内嵌 20 行数据的 `weight` 列被整列错灌成 `sbp` 值（20/20 行 weight==sbp），且**无任何测试消费该基线**（挂空）。用它跑会得 β=1、R²=1。
- **位置**：该 JSON 资产 · **复现**：记录04 §5 · **建议**：修数据并接入测试

#### D13 · 教科书基线数值不可复现（Hosmer logistic）
- **现象**：`logistic_textbook_hosmer.json` 声称 H&L 表 β_age=-0.0271/β_lwt=-0.0152/ll=-117.336，但对权威 MASS birthwt(N=189) 做 low~age+lwt 的 MLE 实为 β=(-0.03979,-0.01278)/ll=-113.562。**存档数值与其声称的模型-数据组合不可复现**，无内嵌数据、无测试消费。（引擎本身算得对——与独立 Newton MLE 一致）
- **位置**：该 JSON 资产 · **复现**：记录04 §5 · **建议**：重录或删除

#### D15 · CORS 允许任意源（ACAO: *）（新发现，扫尾第1轮）
- **现象**：所有 API 响应带 `access-control-allow-origin: *` + `allow-methods: GET,POST,PATCH,DELETE,OPTIONS`。任意网页（含恶意站点）都能从浏览器跨源调用本地 127.0.0.1:8080 API（读数据集、跑分析、导出）。
- **位置**：`server` CORS 配置
- **复现**：`证据/final-sweep.jsonl` cors-acao（Origin: evil.example → ACAO=*）
- **影响**：虽绑定 127.0.0.1 单机，但 DNS-rebinding/恶意本地页面仍可利用；对"数据仅在本机处理"的隐私叙事是缺口
- **建议**：ACAO 收敛到 SPA 自身源（同源）或 Electron 壳白名单，而非通配

#### D16 · 错误码命名风格不一致（新发现，扫尾第1轮）
- **现象**：绝大多数错误码是 CamelCase（`SessionNotFound / SkillInvalidArgs / ResearchApprovalStale`…），但 LLM 探测失败是 SCREAMING_SNAKE `LLM_PROBE_FAILED`。另外 settings 类型错误复用了 `SkillInvalidArgs`（与 skill 无关，语义借用）。
- **位置**：错误码定义 · **复现**：`证据/final-sweep.jsonl` errcode-style · **建议**：统一命名风格；settings 校验用独立错误码

## 三、非缺陷澄清（重要：这些"看起来像问题"其实是正确行为，或是我测试脚本的误判）

为避免误导，明确列出**不是产品 bug**的项：

### 3.1 防呆护栏正常工作（这些"被拦"是对的）
- **0 行数据集审计** → `DATASET_NO_ROWS` blocked ✔（正确拦截）
- **Logistic 结局非二分类**（0/1/2/3 四值）→ 审计 `EVENT_ENCODING_INVALID` blocked ✔（不会沉默算错）
- **Cox 无事件**（全 0）→ 审计 `EVENT_NO_VARIATION` blocked ✔
- **lung 原始 1/2 事件编码** → `EVENT_ENCODING_INVALID` blocked ✔（防止把删失当事件）
- **linear 自变量含不存在的列** → 审计 `ANALYSIS_COLUMN_MISSING` blocked ✔（我扫尾第1轮误判为"200 放行"，实为审计 HTTP 200 但含 blocker，run 从未发生）
- **超长消息 2.1MB** → 413 ✔（正当的体积上限）
- **run 指向不存在数据集** → 422 ✔
- **删除会话后再操作** → 404 ✔

### 3.2 记录04 里那批 stats-public 的 FAIL 是**我脚本的误判**，已修正复验为 PASS
`mtcars-ttest/anova/corr/linear/logistic/tableone/inspect`、`power-*`、`lung-*` 首轮标 FAIL，**原因是我一开始没给公开数据的列名套主键白名单（撞上 D11），审计 blocked 导致 run=None**。改名后（mtcars_api 等）全部复跑 PASS，数值与 R 官方逐位一致。`plantgrowth-anova` 首轮 FAIL 是撞上 D12（weight 列），改名 plant_weight 后 PASS——这两批"FAIL"实际是 **D11/D12 的证据**，不是独立的数值缺陷。

### 3.3 记录03 里 snapshot/sidecar 的首轮 FAIL 也是脚本姿势问题
`snapshot-export` 首轮 FAIL 是我把 destination 传成了目录（正确传文件路径后 PASS，且验证了 sha256 一致性+确定性+download 流）；`sidecar-4langs` 首轮 FAIL 是没传 columns（这**同时暴露了真缺陷 D3**，但带 columns 时四语言全 PASS）。

### 3.4 E2E 的 PARTIAL 大多是我的选择器问题，不是 UI 故障
part2/3/4 里"配置器/Select 数=0"是因为配置器用的是自定义样式按钮而非 `.ant-select` 类，我的选择器没匹配到——**截图证明配置器、三线表、四语言代码全部正常渲染**（记录05）。part6 的"UI 导出快照无下载事件"是我没定位到深层导出按钮，非产品缺陷（API 级导出已全验）。

## 四、环境限制与未覆盖残余风险（可能"落下"的地方，如实列出）

### 4.1 云沙箱环境限制（非产品问题）
1. **官方 vitest 套件没能原样跑**：云端 npm 仓库整域 403（`host_not_allowed`），装不了 vitest/依赖。已用等价手段补偿（parity 129 断言 1:1 重放 + 71 例 HTTP 黑盒 + E2E），但 **property 类随机化测试的海量随机输入、部分单测的细粒度断言没有原样覆盖**。→ **强烈建议你在本机跑一次 `npm test`（ts-backend + web 各一次）作最终盖章**。
2. **真实 DeepSeek/OpenAI 没连**：云端出网被拦，用 localhost mock LLM 走通了协议/编排层，但真实 LLM 的意图识别质量、长上下文、错误重试没测。
3. **桌面 Electron 壳没跑**：Windows 产物无法在云端 Linux 启动，仅代码通读。
4. **大文件压测没做**：70MB 上限附近的上传、大数据集分析的内存/耗时未压测（沙箱额度考虑）。

### 4.2 本轮未及（时间/入口原因）
5. 快照导出的 **UI 按钮路径**（API 级已全验，界面深层入口没点到）
6. 语音录入（需真实麦克风）、移动端窄屏响应式、多实例端口锁的 Windows Job Object 行为
7. 归档态（Archived）相关分支：契约有 `SessionArchived(409)`，但 21 条 HTTP 路由无归档端点，该分支从黑盒不可达，未验证
8. 插件/自动化/分析模板（侧栏可见但本轮聚焦统计主链路，未深入）

### 4.3 继续挖大概率还会有的方向
- 更多"引擎退化数据→500"的子case（D17 只列了 4 个，同类可能更多）
- 并发/竞态（同一会话并发审批、并发 run）
- 快照 zip 的畸形输入 replay、跨版本 replay
- 各算法参数的极端值（alpha=0、power=1、超大样本）

## 五、一句话总评

**数值正确性零缺陷**（17 算法三方 oracle 全对齐），**研究门/审计链设计与实现高度一致且 fail-closed**——这是产品最硬的部分。问题**全部集中在外围工程**：审计启发式的误伤/死锁（D11/D12，用户最容易撞）、输入校验与编码检测（D1/D2/D3）、错误状态码分类（D17/D4/D5/D6）、安全加固（D15）、能力暴露面（G2）、两个失效测试基线（D10/D13）。**没有一个动摇核心统计可信性**，但 D11/D12/D17 会实打实影响真实用户体验，建议优先修。

全程未改动任何业务代码与配置；所有构建脚本、mock、测试 harness 均为独立新增文件，未提交、未推送。
