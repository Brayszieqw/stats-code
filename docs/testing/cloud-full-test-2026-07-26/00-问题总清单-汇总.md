## 〇、先说结论与诚实边界

**核心结论**：统计数值层零缺陷（17 算法经 SAS/SPSS 基线 129 项 + scipy 独立复算 95 项 + R 官方公开数据 16 例三方交叉验证全部一致）；研究门 / 审计链设计与实现高度一致且 fail-closed。**缺陷不在数学，在输入校验、编码检测、审计启发式误伤、能力暴露面，以及两个损坏的测试基线资产。**

**是否"一个细节都没落下"？——不是。** 以下内容本轮**没有覆盖**，属已知盲区（详见第五章）：
1. 官方 vitest 四套件（unit/integration/property/parity）与 web vitest **未原样执行**（云沙箱 npm 仓库被整域 403，装不了依赖）——已用等价手段补偿，但 property 随机化断言、组件级断言的原始粒度没跑到。
2. 桌面 Electron 壳（Windows 产物，云端 Linux 起不来）——仅代码通读。
3. 语音录入（需真实麦克风）、移动端窄屏响应式、Windows 端口锁 Job Object 行为。
4. 真实 DeepSeek/OpenAI 连通（云端出网被策略拦，用 mock LLM 走通协议层）。
5. 快照导出的 UI 按钮入口（API 级已全验，UI 深层按钮本轮没点到）。
6. 70MB 上限附近大文件上传压测。
7. 7 个引擎算法（见 G2）因无 UI/HTTP 通路，只在引擎级验证，没能"从界面点着测"。

## 〇·五、补测轮新增确认缺陷（v2，均已独立复现）

### S1 — CORS `Access-Control-Allow-Origin: *`：任意网页可跨源调用本地 API（安全）
- **级别**：高（安全）
- **位置**：`ts-backend/packages/server/src/router.ts`（CORS 头设置，ACAO=`*`、ACAM=`GET,POST,PATCH,DELETE,OPTIONS`、ACAH=`*`）
- **复现**：`curl -H "Origin: https://evil.example.com" http://127.0.0.1:8080/api/health -I` → 响应头 `access-control-allow-origin: *`
- **实际 vs 期望**：本产品是**无认证的 localhost 应用**，数据仅在本机。ACAO=* 意味着用户浏览器里打开的**任意恶意网页**都能跨源向 `127.0.0.1:8080` 发请求，读取/删除会话、上传数据、导出快照、甚至改 LLM 配置。期望：localhost 应用应把 ACAO 限制为自身来源（或不发 CORS 头 / 仅允许 `null`/`http://localhost:*`），并对写操作加 CSRF/同源校验。
- **影响**：DNS-rebinding / 恶意页面可静默操纵用户本地统计会话与数据。对"数据仅在本机处理"的隐私叙事是实质性削弱。
- **证据**：本轮 §核实（活服务器复现，ACAO=*）
- **建议**：收紧 CORS 到同源；对状态变更路由加同源/CSRF 防护。

### S2 — spawn 哨兵 `.exe` 剥离仅在 Windows：非 Windows 上 `python.exe` 不被拦（安全相邻 + 测试跨平台）
- **级别**：中（安全相邻）
- **位置**：`ts-backend/packages/engine/src/spawn_policy.ts` `normalizeCommand`（`.exe` 后缀仅当 `IS_WINDOWS` 时剥离）；单测 `tests/unit/spawn-policy.test.ts:49` 断言与平台无关
- **复现**（直接对引擎）：`checkSpawn("C:\\Python311\\python.exe")` → **未拦截(ALLOWED)**；`matchForbiddenCommand("C:\\Python311\\python.exe")` → `null`。对照 `/usr/bin/python3` → 正确 BLOCKED。
- **实际 vs 期望**：spawn 哨兵是阻断外部统计运行时(R/SAS/Python/SPSS)的安全控制。`normalizeCommand` 在非 Windows 上不剥 `.exe`，于是 `python.exe`→`python.exe`(不在黑名单)→放行。测试 `matchForbiddenCommand('C:\\...\\python.exe').not.toBeNull()` 是平台无关断言，**在 Linux/Mac CI 上会真失败**（forbidden-spawn property 测试同样因此失败）。
- **影响**：产品是 Windows 目标，真机上 `.exe` 会被剥离→拦截，实际风险低；但(a)跨平台 CI 会挂这条测试，(b)防线在非 Windows 宿主弱于设计意图。
- **证据**：记录08 §1（unit 唯一真失败）；直接引擎复现
- **建议**：`.exe` 剥离改为平台无关（始终尝试剥离已知可执行后缀再比对），保证哨兵跨平台一致。

### D15 — 退化/非法输入一律 500 `SkillExecutionFailed`（应 422）
- **级别**：中
- **位置**：`ts-backend/packages/server/src/conversation/skill-runner.ts` → `router.ts` 错误映射（引擎正确抛错，但 HTTP 层归为 500 而非 4xx）
- **复现**（全链路 run）：
  - ttest 单组（只有一个组）→ `500 "T test requires exactly two non-empty groups in g; got 1"`
  - ttest 单例组（某组仅 1 观测）→ `500 "Welch's t-test requires at least 2 observations per group."`
  - linear 完全共线（x2=2·x1）→ `500 "Design matrix is rank deficient (rank 1 of 2)..."`
  - correlation 零方差列 → `500 "Pearson correlation requires x to have non-zero variance..."`
  - correlation 非法 method=banana → `500 "unsupported correlation method 'banana'; expected 'pearson' or 'spearman'"`
  - anova 含非数值文本 → `500 "non-numeric value in column y at data row 2"`
- **实际 vs 期望**：引擎**行为正确**（明确拒绝、消息清晰，没有静默出错误结果——这是好事），但这些都是**用户输入问题**，HTTP 应返回 422/400，不该是 500（500 语义是服务器内部错误，会误导监控/客户端重试逻辑）。
- **影响**：错误分类不当；用户/前端难以区分"我的数据有问题"和"服务器坏了"。
- **证据**：final-sweep 复现 + 本轮活服务器逐条复现
- **建议**：把这类"输入导致的引擎拒绝"统一映射为 422（可在 skill-runner 抛一个可识别的 InvalidInput 错误类型，router 据此给 422）。

### D16 — 快照导出 UI 主按钮「下载审计快照」报未处理文件系统错误（旗舰功能）
- **级别**：中高（这是"信任三件套"之一，主按钮在正常点击下出错）
- **位置**：`ts-backend/packages/engine/src/snapshot/exporter.ts`（destination → `<dest>.tmp` → rename；mkdir/rename 未容错）；前端 `web/src/hooks/useSnapshotExport.ts` 传的 destination
- **复现**：专业模式跑完一次分析 → 第 5 步"诊断与导出" → 点「下载审计快照」→ 浏览器红字 `导出失败 EEXIST: file already exists, mkdir '/home/claude/stats-code/repo/ts-...'`（截图 97）。API 侧独立复现导出器脆弱点：destination=已存在目录→`500 EISDIR`；父目录不存在→`500 ENOENT`；正常文件路径→200（重复导出也 200）。
- **实际 vs 期望**：审计快照是产品可信性的核心交付物。主下载按钮在真实用户点击下抛出未处理的 EEXIST/EISDIR/ENOENT。期望：导出前 `mkdir recursive + 容忍已存在`，destination 归一化为文件路径，失败给用户友好提示而非裸 errno。
- **影响**：用户拿不到审计包（或看到吓人的英文文件系统错误），旗舰卖点在 happy path 上翻车。
- **证据**：截图 97（浏览器错误原文）+ 本轮 API 四种 destination 复现表（记录08 §5）；与 D5 同源，此处**升级严重度**因它是 UI 主路径实触发
- **建议**：exporter 用 `mkdirSync(dir,{recursive:true})` 建父目录、对已存在目录/文件做归一化与容错；download 模式优先走内存流不落地。

### D2 扩展 — UTF-16 与 GBK 同样误判 Utf8 乱码
- 见下方 D2；补测确认 UTF-16LE(带 BOM) CSV 上传同样 `encoding=Utf8`、中文列名乱码（`['组','值']`→`['\ufffd\ufffd~','\x00...']`）。编码探测只认 UTF-8，Gbk/Utf16 两个枚举值都从未兑现。

## 一、高优先级问题（会真实挡住用户或误导能力认知）

### G2 — 引擎 17 个算法里只有 8 个能从界面/HTTP 跑到
- **级别**：高（产品能力面）
- **位置**：`ts-backend/packages/server/src/conversation/skill-runner.ts`（分发 switch 只实现 8 个）；`web` 专业配置器只有 7 个模块按钮；对照 `packages/engine/src/stats/index.ts` 的 `ALGORITHM_IDS`（17 个）与 `/api/coverage-matrix`（宣示 17 个）
- **复现**：
  1. `POST /api/sessions/:sid/run` 传 `skill_id:"or_rr"`（或 nonparametric / attributable_risk / standardization / life_table / diagnostic_roc）→ 返回 `422 SkillInvalidArgs "未知统计方法：or_rr"`
  2. 专业工作台配置器只有：基线特征 / T 检验 / 方差分析 / 相关分析 / KM 生存 / 回归建模 / 功效分析 —— 无非参数、无 OR/RR、无 ROC、无标化、无寿命表
- **实际 vs 期望**：引擎实现了 17 个且数值全部正确（parity 已验），但 coverage-matrix 和等价代码侧栏对外宣示 17 个可用，实际界面/HTTP 只能跑 8 个（power 三兄弟还合并成一个 `power` skill）。能力宣示 > 可运行面。
- **影响**：用户在覆盖矩阵看到 ROC/OR-RR/非参数"可用",但界面里找不到入口、API 直接拒绝。信任叙事受损。
- **证据**：记录04 §5；`证据/stats-public.jsonl`（or_rr 只能引擎级验证那条）；记录03 coverage-matrix=17
- **建议**：二选一——(a) 补齐 skill-runner 分发与配置器模块，把 9 个补上；(b) 覆盖矩阵/文档显式区分"引擎级能力 / 界面可运行能力",不让用户误以为都能点。

### D12 — 列名叫 `weight` / `wt` 一律被当抽样权重，整库阻断且不可覆盖
- **级别**：高
- **位置**：`ts-backend/packages/server/src/conversation/dataset-audit.ts`，权重启发式（`findSemanticHeader` 的 weight 候选含 `'weight','weights','wt'` + 正则 `/^...(weight|weights|wt)$/`）
- **复现**：
  1. 上传任何含 `weight` 或 `wt` 列的 CSV（如 R 的 PlantGrowth 结局列就叫 weight；mtcars 车重列 wt）
  2. 对任意 skill 发起 `/audit` → 返回 `status:"blocked"`,findings 含 `SURVEY_DESIGN_UNSUPPORTED`("检测到抽样权重/PSU,但当前统计引擎未实现复杂抽样方差估计")
  3. 该 finding 是 blocker,审批被 409 挡死,且无法覆盖
- **实际 vs 期望**：把"变量名恰好含 weight/wt"等同于"这是抽样权重"。但出生体重、植物重量、体重、砝码…在生物统计里极常见地作为**结局/协变量**。期望：结合角色声明或让用户否认,而非纯列名硬判。
- **影响**：PlantGrowth（统计教学最经典的 ANOVA 数据集,结局列就叫 weight）在本产品里**原样永远无法分析**;体重类结局的真实医学数据大面积误伤。
- **证据**：记录04 §3（plantgrowth-anova 首次 blocked,改名 plant_weight 后才过 F=4.846）;记录04 §5 D12
- **建议**：权重判定必须结合用户显式角色映射(roles.weight),不能只看列名;或在审计卡给"这不是抽样权重"的一键否认。

### D11 — 主键只认 7 种命名，且用户指定也被拒 → 无白名单列名的数据集在界面里死锁
- **级别**：高
- **位置**：`ts-backend/packages/server/src/conversation/dataset-audit.ts`，主键启发式候选仅 `['participant_id','subject_id','patient_id','person_id','record_id','study_id','case_id']` + 正则 `/^(participant|subject|patient|person|record|study|case)_(id|key)$/`；覆盖被 `AUDIT_ROLE_OVERRIDE_REJECTED` 拒绝
- **复现**：
  1. 上传列名为 `id` / `rownames` / 无 ID 列的数据集（绝大多数真实公开数据）
  2. `/audit` → `blocked`,findings 含 `PRIMARY_KEY_UNBOUND`("未能由服务端可靠识别主键;建立版本化字段映射前禁止审批")
  3. 尝试 `roles.primary_key:['rownames']` 覆盖 → 追加 `AUDIT_ROLE_OVERRIDE_REJECTED`("primary_key 角色必须与服务端…映射一致"),依旧 blocked
- **实际 vs 期望**：服务端识别不出主键 → 阻断;用户明确指定 → 也拒。期望:允许经确认的用户 PK 绑定（记录进审计哈希链即可保证可复现),或上传时引导选主键。
- **影响**：只要列名不在那 7 个白名单里,用户在 UI 内**无自助出路**,只能改列名重传,而界面没有任何引导提示他该这么做。这是我在跑 mtcars/lung/birthwt 时全部撞上、必须改名 participant_id 才能继续的墙。
- **证据**：记录04 §3（多个 audit blocked → 改名后 passed）;`证据/stats-public.jsonl`
- **建议**：放开"经用户确认的 PK 绑定"路径并写入审计;UI 在 blocked 时明确告诉用户"请指定主键列"。

## 二、中优先级问题（输入校验 / 编码 / 契约健壮性）

### D1 — 非法 base64 被宽松解码成乱码数据集，还返回 201 成功
- **级别**：中
- **位置**：`ts-backend/packages/server/src/conversation/dataset-store.ts`（base64 解码未校验）
- **复现**：`POST /api/sessions/:sid/datasets`,body `{"filename":"x.csv","data":"!!!not-base64!!!"}`
- **实际**：`201`,生成一个 `row_count:0`、列名为乱码 `��~m�` 的数据集。**期望** `422`。
- **根因**：Node `Buffer.from(s,'base64')` 遇非法字符静默忽略而不报错。
- **影响**：脏输入进库,后续分析基于垃圾数据;攻击面/数据完整性问题。
- **证据**：记录03,`证据/api-contract.jsonl` 案例 `dataset-bad-base64`
- **建议**：显式正则校验 base64,非法即 422。

### D2 — GBK 编码 CSV 被判成 Utf8，中文列名全乱码
- **级别**：中偏高（中文用户高频场景）
- **位置**：`ts-backend/packages/server/src/conversation/dataset-store.ts` 编码探测
- **复现**：把 `组别,数值\n甲,1\n乙,2` 以 GBK 编码上传
- **实际**：`encoding:"Utf8"`,列名解析成 `���` / `��ֵ`。契约 `Encoding` 枚举里明明有 `Gbk`,但**从未产出过**。**期望**：识别为 Gbk 并正确解出中文。
- **影响**：Windows 上 Excel 另存 CSV 默认常是 GBK/ANSI,中文列名/数据直接乱码,这是中文用户最典型的踩坑。
- **证据**：记录03 `dataset-gbk`;记录03 复核 `dataset-gbk-columns`(列名 `['���','��ֵ']`)
- **建议**：加 BOM / GBK 启发式;或对无效 UTF-8 字节序列回退 GBK 解码。

### D3 — 等价代码 sidecar 传空 columns（schema 默认值）直接 500
- **级别**：中
- **位置**：`ts-backend/packages/server/src/contract/sidecar.ts`（`columns` 默认 `[]`）+ `packages/engine/src/sidecar/render.ts`
- **复现**：`POST /api/sidecar/ttest`,body 只给 `{"software":"R","dataset_sha256":"..."}`（columns 用 schema 默认空数组）
- **实际**：`500 InternalError "column index 0 is out of range (have 0 columns)"`。**期望**：契约允许的最小合法输入不该把服务器打 500。
- **影响**：契约声明 columns 可缺省,实际缺省即崩;前端若不传 columns 会 500。
- **证据**：记录03 `sidecar-ttest-4langs`(首轮四语言全 500)→ 复核 `sidecar-with-columns` 传了 columns 就正常
- **建议**：空列时给占位渲染,或 schema 要求 columns 非空。

### D10 — Kleinbaum 教科书线性回归基线：内嵌数据整列损坏，且无人使用
- **级别**：中（测试资产腐化）
- **位置**：`ts-backend/tests/parity/known_values/linear_textbook_kleinbaum.json`
- **复现**：读该文件的 `dataset.rows`——20 行里 `weight` 列的值 **20/20 全部等于 `sbp` 列**（例如 `[144,39,144]`,144 既是 sbp 又是 weight）
- **实际**：用这份数据做 SBP~age+weight 会得到 β_weight=1、R²=1 的退化结果;声称的 `expected` 是 β_age=0.8614/β_weight=0.3342/R²=0.9981,两者对不上。而且**没有任何测试消费这个基线**(挂空)。
- **影响**：假基线,若将来接入测试会误判;当前是"看着像验证资产实则失效"。
- **证据**：记录04 §5 D10;`build/parity-extra.mjs` 跑出 β=0/1、R²=1
- **建议**：修复数据（补真实 weight 列）并接入 parity;或删除。

### D13 — Hosmer 教科书 Logistic 基线：数值与其声称的模型-数据组合不可复现
- **级别**：中（测试资产腐化）
- **位置**：`ts-backend/tests/parity/known_values/logistic_textbook_hosmer.json`
- **复现**：文件声称 H&L Table（low~age+lwt）：β_age=-0.0271、β_lwt=-0.0152、logLik=-117.336;但对权威 MASS birthwt(N=189) 做同一模型的 MLE,实为 **β=(-0.03979,-0.01278)、logLik=-113.562**（引擎、scipy、独立 Newton 三方一致）。存档值两头对不上,且无内嵌数据、无测试消费。
- **影响**：同 D10,失效基线。
- **证据**：记录04 §3 `birthwt-logistic-hosmer`(引擎与独立 MLE 一致,但都不等于存档 hosmer 值)
- **建议**：用明确的数据+软件重录,或删除。

## 三、低优先级问题（错误分类 / 文案 / 文档 / 响应头）

### D4 — sidecar 未知算法返回 500 而非 404/422
- **级别**：低中 · **位置**：`sidecar` 路由/引擎 · **复现**：`POST /api/sidecar/not_an_algo` → `500 InternalError "unknown algorithm: not_an_algo"` · **期望** 404/422（用户输入错误不应表现为服务器内部错误）· **证据**：记录03 `sidecar-unknown-algo` · **建议**：错误分类改为 4xx。

### D5 — 快照导出 destination 传目录/空串 → 500 裸 errno
- **级别**：低 · **位置**：snapshot export handler · **复现**：`destination` 传已存在目录 → `500 "EISDIR ... rename"`;传空串 → `500 ENOENT` · **期望** 400 参数校验 · **备注**：桌面端总传文件路径,平时不触发;属输入校验缺口 · **证据**：记录03 调试段 · **建议**：导出前校验目标为可写文件路径。

### D6 — 空消息体返回 413 MessageTooLong，但文案是"缺少 text 字段"
- **级别**：低 · **位置**：`POST /api/sessions/:sid/messages` · **复现**：`POST {}`（空 body）→ `413`,error_code=`MessageTooLong`,message="请求体缺少 text 字段" · **期望**：缺字段是 400/422,不该用"太大"的 413 · **证据**：记录03 `message-empty` · **建议**：错误码与语义对齐。

### D8 — `--replay` 文档与实现不一致，且未知 flag 被静默当成启动服务
- **级别**：低 · **位置**：`CONTEXT.md`(写 `--replay`) vs `packages/engine/src/cli.ts`(实际是 `replay <zip>` 子命令) · **复现**：`stats-code --replay x.zip` → `--replay` 未被识别为 flag,`x.zip` 不是已知子命令 → **静默落入 launcher 模式启动服务器**(我第一次就这么挂起了一个 8081 端口的进程) · **期望**：文档写对 + 未知 flag 显式报错 · **证据**：记录03 D8;记录03 replay 段(正确语法 `replay <zip> [--sha256]` 验证 PASS/FAIL/exit2 全对) · **建议**：文档改 `replay <zip>`;CLI 对未识别 flag 报错退出。

### D14 — /assets/* 缺失时兜底返回 index.html 而非 404
- **级别**：低 · **位置**：`ts-backend/packages/server/src/spa.ts` 兜底逻辑 · **复现**：请求不存在的 `/assets/xxx.woff2` → 返回 200 + index.html(HTML 冒充字体)→ 浏览器刷一串 `OTS parsing error: invalid sfntVersion` · **期望**：`/assets/` 前缀 miss 返回 404 · **影响**：调试噪声大(E2E 里 121 条字体告警全是这个);本轮字体分片没拉云是诱因,但兜底策略本身也该收敛 · **证据**：记录05 D14;各 e2e-console.json · **建议**：asset 前缀未命中直接 404,只对非 asset 路由回退 SPA。

### D9 — SSE 响应头缺 charset=utf-8

## 四、观察项（不算缺陷，但值得注意 / 需持续盯）

### O2 — t 检验组序按"数据首现顺序"，符号可能与 R/SPSS 习惯相反
- **位置**：`skill-runner.ts` `runTtest` · **现象**：mtcars 首行 am=1,引擎按首现序算得 t=+3.767;R 按水平值排序算得 -3.767。**|t|、p、df 完全一致**(3.767123/0.00137364/18.3323),payload 也申明了 `groups` 顺序 · **风险**：用户拿去和 R/SPSS 对照时看到符号相反会困惑 · **建议**：按组标签值排序,或 UI 明确标注差值方向。

### O3 — 简易模式追问卡让用户填"数据集 ID"（UUID 语义过技术化）
- **位置**：简易模式追问卡 · **现象**：聊天触发分析缺参数时,卡片写"执行「T 检验」还需要以下信息:数据集 ID…" · **风险**：小白用户不知道 UUID 是什么 · **建议**：追问时直接给数据集选择器而非要求填 ID · **证据**：截图 08。

### O4 — 两次未复现的偶发：一次 pageerror(Object)、一次 download 读超时
- **现象**：E2E Part4 捕获过 1 次内容为"Object"的 pageerror,同路径 Part5/6 未复现;记录03 snapshot download 首次出现 60s 读超时,之后 curl+requests 连测 4 次均 <20ms 正常 · **风险**：可能是环境偶发,也可能是低频竞态 · **建议**：前端加 `window.onerror` 结构化上报;后端 download 路径加并发/大文件观测,便于将来定位。
