## 3. 环境阻塞与替代方案（重要）

| # | 阻塞 | 影响 | 替代方案 |
|---|---|---|---|
| B1 | 云沙箱出网策略把 registry.npmjs.org、pypi.org 等包仓库整域 403（`x-deny-reason: host_not_allowed`），npm ci / pip install 全部不可用 | 无法在云端重装依赖 → vitest 全量测试套件（unit/integration/property/parity）与 Vite 构建**无法以官方方式运行** | ① 用设备上已构建的 `ts-backend/build/bundle.cjs`（esbuild 单文件后端）与 `web/dist`（已构建 SPA）直接部署——**功能与 E2E 测试不受影响**；② parity 平价套件用 Python 按 known_values 基线经 HTTP 重放等价复现；③ 算法正确性用云端自带 scipy/numpy 独立复核（statsmodels/lifelines 不可装，Cox/KM 用基线+手工实现对照） |
| B2 | 设备本地 Linux 工作区（device_bash）启动失败 | 无法在设备端打包 zip 一次性传输 | 改用文件桥逐文件 staging（已完成 412/439） |
| B3 | staging 进行中设备桥断开（最后一批 39 个文件 + build 产物未拉到） | web/src/views/pro、views/simple、web/scripts、bundle.cjs、web/dist 暂缺 | 持续重试；桥恢复后第一时间补拉 |
| B4 | 云端无 DeepSeek/OpenAI 真实 API Key，且外网 LLM 域名大概率同样被策略拦截 | 聊天链路的"真 LLM"端到端无法测 | 在云端起 OpenAI 兼容 mock LLM 服务（localhost 不受出网策略影响），经 UI 正常配置流程写入 base_url 指向 mock，完整走通聊天/编排/审批链路；同时测"无效 key"错误路径。此为测试所需的运行时配置（走产品自身的配置接口），不改动业务代码 |
