## 1. 关键决策：不用过期产物，从当前源码重打后端

设备上已有的 `ts-backend/build/bundle.cjs` 构建于今天 04:04(UTC)，但其后源码还有十余处改动
（`engine/stats/cox.ts、logistic.ts、anova.ts、math/distributions.ts、coverage/matrix-data.ts、
sidecar/templates-data.ts、server/conversation/skill-runner.ts` 等，最晚 06:55）——直接测它会测到**旧代码**。

云端 npm 仓库被网络策略封锁（记录01 B1），无法 `npm ci`。采用的替代构建链（不改动任何业务代码）：

1. `build/stale-vendor-lib.cjs`：把旧 bundle 在入口执行前截断，只导出其中完整的
   fastify(29 文件) / yaml(72 文件) 两棵 CJS 依赖树工厂——第三方库代码与生产一致；
2. zod(3.25.76) / zod-to-json-schema(3.25.2) / smol-toml 从设备 node_modules 原样拉取（71 个文件）；
3. 用云端预装 tsx 自带的 esbuild，从 `packages/api/src/bin.ts` 按**当前 TS 源码**打包
   `build/fresh-bundle.cjs`（823KB；`@stats-code/*` 直接 alias 到 src；koffi 按官方 external 语义 stub，
   代码内本就有 graceful fallback）；
4. `node scripts/embed-assets.mjs` 用官方脚本生成 `build/assets`（SPA 资产清单 8 项）；
5. `node build/fresh-bundle.cjs --no-browser` 启动。

> 与官方 `npm run bundle` 的差异仅两点：esbuild 版本（tsx 内置 vs 仓库 0.24）与 koffi 的缺席方式
> （stub-throw vs external-未安装），运行语义一致。第三方依赖字节级来自设备真实 node_modules/旧产物。
