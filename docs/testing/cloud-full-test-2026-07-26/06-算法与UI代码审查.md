## 1. 算法实现审查（engine/src/stats，17/17 全覆盖）

### 1.1 边界防护密度扫描（throw/长度校验/Number.isFinite/除零分支 计数）
ttest 14 · anova 8 · correlation 9 · nonparametric 8 · linear 9 · logistic 16 · cox 24 · survival 19 · power 16 · epi 11 · contingency 11 · diagnostic 12 · tableone 14 · standardization 6 —— 防护普遍到位，重点抽查确认：

| 文件 | 审查要点 | 结论 |
|---|---|---|
| ttest.ts | Welch df 公式（数值验证 df=18.3323 与 R 一致）；`se<=0 或 !isFinite(se)` 显式抛错（零方差组防护）✔ | 好 |
| anova.ts | 空组抛错；注释明确处理"msWithin===0 只捕获组内重复值恰相等"的浮点细节 ✔ | 好 |
| correlation.ts | 分母 `<=0/!isFinite` 防护；Fisher z 95%CI（单测以 atanh 公式核对到 1e-12）✔ | 好 |
| linear.ts | 每系数 stdError 不可有限时标记 `degenerate` 而非崩溃；F 不可有限时整体降级 ✔（这解释了 D10 坏基线数据也能温和输出） | 好 |
| logistic.ts | 设计阵含非有限值/权重≤0 显式抛错；stdError 非有限降级；skill 层追加 **separation_screen 完全分离筛查**诊断 ✔ | 好 |
| cox.ts | **Efron ties**（文件头注明与 R survival / lifelines 一致——已被 lung 数据 R 公认值验证）；24 处防护含 time<0、weight≤0、风险集 S0≤0、maxEta 溢出保护；PH 假设检验输出 cox_ph_violated + 风险信号 ✔ | 好 |
| survival.ts | KM 方差(stdError)、median 交叉、log-rank（χ²=10.33 与 R survdiff 一致）；lifeTable 区间参数化 ✔ | 好 |
| power.ts | phase3 用**非中心 t**（与 SAS PROC POWER 基线 1e-3 带内一致）；单臂/二期用 arcsine 近似——与 SAS 同法，但与 G*Power 精确二项法会有差异，建议文档标注方法学出处 | 好（建议补文档） |
| epi.ts | 2×2 任一行全零抛错；含零格 Haldane 连续性校正分支；CI 用 Woolf/Wald（代码注释坦白与 SAS 1e-5 级方法差异，parity 有意不比 CI —— 诚实的工程处理）✔ | 好 |
| contingency.ts | fisherExactTwoSided 接口收 2×2 表并校验行宽（我在记录 04 用 Agresti 茶品鉴表验证 p=0.4857 ✔）；卡方独立性检验含期望频数逻辑 | 好 |
| diagnostic.ts | AUC 用秩法（Mann-Whitney 等价，处理并列）；与 sklearn roc_auc_score 一致 ✔ | 好 |
| math/ | distributions（t/F/χ²/正态/非中心 t）、linalg（最小二乘/求逆）、special（不完全 β/Γ）——全部数值端点已被 129 项基线断言间接验证 | 好 |
| spawn_policy.ts | FORBIDDEN_RUNTIMES 哨兵主动阻断 R/SAS/SPSS/Python 等外部统计运行时 spawn（"不 shell out"承诺的强制层）✔ | 好 |
| redact.ts | 密钥/敏感信息脱敏策略 + 属性测试（llm-key-redaction）设计合理 | 好 |

### 1.2 算法层审查结论
数学实现干净、防护充分、方法学选型（Efron ties、Welch 默认、非中心 t 功效、Haldane 校正）主流且与参照软件对齐；**没有发现数值层缺陷**。问题集中在上层：G2（7 算法无 HTTP/UI 通路：nonparametric、or_rr、attributable_risk、standardization、life_table、diagnostic_roc + power 三兄弟只以合并 skill 暴露）与两个失效教科书基线（D10/D13）。
