## 2. 结论一句话

**统计数值层：零缺陷**（三方 oracle 全对齐）；**研究门/审计链：设计与实现高度一致且 fail-closed**；缺陷集中在输入校验、编码检测、审计启发式误伤和能力暴露面，均为可修的工程问题，不动摇核心可信性。

## 6. 残余风险与建议下一步

1. 在你本机原样跑一遍 `npm test`（ts-backend、web），补上 property/组件级断言的最终盖章（预计全绿——核心行为已被本轮黑盒+重放约束）。
2. 优先修 D12/D11（审计启发式），这是真实用户最容易撞上的墙；其次 G2 决策（补通路或明示能力分层）。
3. 输入校验三连（D1/D2/D3）建议一并处理，都是 dataset/sidecar 入口的防御问题。
4. 两个教科书基线资产（D10/D13）修复后接入 parity 测试，避免"死基线"再次腐化。
5. 桌面壳与真实 LLM 场景请在 Windows 本机按 `启动Stats桌面.bat` / 真 Key 复核一次（云端无法代替）。
