# Stats Code 已知限制与防护说明

日期：2026-07-26 ｜ 适用版本：kiro/dual-mode-frontend 工作区（ts-backend 635 + web 326 = 961 测试全绿基线）

## 设计边界（有意为之，非缺陷）

1. **LLM 不接收数值载荷、不计算数字。** 所有统计量由本地确定性引擎计算；LLM 仅做意图识别与方法学提示。LLM 输出若含数字、诊疗措辞或超长文本会被自动丢弃，回退到内置的确定性方法注记。
2. **正式分析必须通过服务端研究门**（协议审批 → 数据审计 → 分析计划批准），任何入口绕不过；只读的数据概览（inspect）豁免审批，但运行记录带 `gate: "exempt"` 审计标记。
3. **运行注册表在内存中**：后端重启后历史运行的快照导出返回 404 与中文提示（"请重新运行分析后再导出"），属预期行为而非故障。

## 已知限制（当前版本）

1. 前端打包体积偏大：index ≈1.5 MB、antd ≈1.0 MB（构建时有 >600 kB 警告），另有一个 1 字节的空 react chunk（manualChunks 配置遗留）。只影响首屏加载速度，不影响功能与正确性。
2. 快照下载会在后端工作目录 `exports/` 留存 zip（按 runId 命名，同一 run 重复导出覆盖），暂无自动清理。
3. 相关分析的 `method` 参数仅支持 pearson/spearman；收到其他取值按 pearson 处理而不报错。
4. 未配置 LLM 时的离线关键词路由中，"组间对比"一词固定路由到 t 检验；三组及以上数据会得到明确报错，需改说"方差分析"。
5. 数值口径：normalCdf 为 1e-9 级近似（inverseNormal 已达双精度），对常规 p 值展示无实际影响。
6. 消息缺 `text` 字段时返回 413（语义上更应为 422），错误文案本身正确可读。
7. 列类型自动推断偏保守：低基数整数列（≤6 个不同取值、≥20 非缺失行、存在重复）判为分类变量，其余整数列与含小数列判连续；判错时可在专业模式配置器手动调整。
8. 仅支持 CSV/文本表格且 ≤70 MiB（超限与格式错误均有明确报错）。
9. 桌面（Electron）壳与语音录入（需麦克风权限）未纳入本轮真机回归。
10. 低配或高负载机器上跑全量测试时，快照类用例的 PowerShell 解压首次冷启动可达 24–28 秒；测试超时已设 60 秒兜底。

## 防护措施摘要（已验证）

- 全部 API 入口有输入校验与结构化中文错误：畸形 JSON→400、缺字段→413、超长消息（>8000 字符）→413、非法 runId→400、未批准运行→428/403、会话不存在→404，均经真机探针验证，服务全程不崩。
- SSE 流中途失败发送结构化 error 帧并正常终止（`done` 帧仍到达），前端 ErrorBanner 有对应展示与"去审批"引导按钮。
- 连续多轮对话（含审批门拒绝、真实 LLM 调用）后会话状态一致，删除会话后干净返回 404。
- 打包脚本内置密钥扫描与禁运文件名单（llm-config.json/.env 等），安装脚本拒绝携带密钥文件；API Key 仅存于本机 `%APPDATA%\stats-code\`，不进安装包。
- 构建守卫以内容指纹 + 产物清单校验判断 dist 新旧，防止陈旧构建被误用。
