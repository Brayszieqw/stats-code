# 发展路线图

> Stats Code（**TS 生产路径**）从「功能可用」到「专业可信」的阶段规划。  
> 旧版 Rust T1–T6 / `implementation_plan.md` 已归档删除；以下为 2026-07 起的有效路线。

## 现状（基线）

- 后端：`ts-backend` 三层 `api → server → engine`
- 算法：17 个 Output-Level 算法（见 [[统计引擎]]）
- 前端：Simple / Pro 双模式
- 信任层：sidecar 四语言、coverage matrix、snapshot、spawn 哨兵、parity 套件

## 阶段

| 阶段 | 主题 | 优先级 |
|------|------|--------|
| **T1** | 多步分析计划 + 跑前 checkpoint | 最高 |
| **T2** | 统计守卫（前提检查、多重比较、小样本/措辞） | 最高 |
| **T3** | 缺失画像与数据清洗 skill | 高 |
| **T4** | STROBE/方法学报告草稿（绑定真实参数） | 高 |
| **T5** | PSM/IPW + 平衡诊断；竞争风险或 PH 诊断 | 中高 |
| **T6** | 输入格式 sav/dta/xpt；可视化与出版级表图增强 | 中 |
| **T7** | DAG/混杂辅助（可选文献插件）；教学解释加深 | 中远期 |

## 最小可行路径

T1 → T2 → T3：约可把「会算」提升为「敢给临床/epi 用户用」的可信门槛。

## 开放问题

- 目标用户权重（教学 / 临床科研 / 公卫现场 / 药企流水线）
- 是否进入 TFL/SAP 监管交付
- 文献检索类能力是否插件化（勿拖垮核心引擎）
