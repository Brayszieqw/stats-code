# 发展路线图

> 源自 `implementation_plan.md`。Stats Code 从"功能完整"到"优秀"的阶段规划 T1~T6。

## 现状
~40000 行 Rust,4 crate,30+ 命令,157+ 测试,Clippy pedantic 零 warning。主要短板:God File(`handlers.rs` ~3420 行、`report.rs` ~3748 行)、测试覆盖不均。

## 阶段

| 阶段 | 主题 | 工作量 | 优先级 |
|------|------|--------|--------|
| **T1** | 内功清理:消除技术债务(God File 拆分、错误处理标准化、模块文档、覆盖率基线) | 3-4h | 🔴 最高 |
| **T2** | 统计方法扩充(KM+Log-rank、卡方/Fisher、PSM/IPW、ROC/AUC) | 8-12h | 🟡 高 |
| **T3** | 数据处理增强(XPT/SPSS/Stata 格式、数据变换、缺失数据) | 4-6h | 🟡 高 |
| **T4** | 可视化与报告(ASCII 图表、SVG 导出、STROBE 模板、LaTeX 表格) | 6-8h | 🟢 中 |
| **T5** | 发布与分发(跨平台 CI、包管理器、CHANGELOG) | 3-4h | 🟢 中 |
| **T6** | Web 界面与社区(WASM 前端、mdbook 文档、示例集) | 10-15h | 🔵 远期 |

## 最小可行路径
T1(清理)→ T2.1(KM+Log-rank)→ T4.1(ASCII 图表),约 10 小时可从"功能完整"跃升为"有竞争力"。

## 开放问题
- 统计方法优先级(生存/分类/因果/诊断 哪个最急)
- 错误处理重构时机(`thiserror` 影响全局)
- Web 前端定位(教学平台 vs 专业 CLI)
- `plugins`/`runtime` crate 去留
